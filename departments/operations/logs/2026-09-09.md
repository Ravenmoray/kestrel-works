## Constraint hit running this turn — and the workaround

`.claude/skills/workday/SKILL.md` and `.claude/agents/ops-coordinator.md`
both specify delegating via the `Agent` tool with `subagent_type` set to the
target department persona (e.g. `research-lead`, then `ops-coordinator`
itself). That did not work this session: this session's tool definitions
listed only generic agent types (`claude`, `claude-code-guide`, `Explore`,
`general-purpose`, `Plan`, `statusline-setup`) — none of the six Kestrel
Works personas, even though all six `.claude/agents/*.md` files (and both
`.claude/skills/*/SKILL.md` files) already existed on disk for the entire
session (written earlier today, before this session opened).

**Root cause:** Claude Code indexes project-scoped agents and skills from
`.claude/agents/` and `.claude/skills/` once, at session start. It does not
re-scan mid-session, so files present before the session started but not yet
picked up by the harness's persona index are simply unavailable as
`subagent_type`s or `Skill` invocations for the life of that session.

**Workaround used:** rather than calling the `Agent` tool with a
`subagent_type` that doesn't exist in this session, the acting agent read
the relevant persona file(s) directly (`departments/research/CHARTER.md` +
`.claude/agents/research-lead.md` for the Research turn, then
`departments/operations/CHARTER.md` + `.claude/agents/ops-coordinator.md`
for this bookkeeping) and carried out the work in-character, by hand,
instead of delegating through the tool. Output is identical in substance;
what's lost is the harness-level role isolation (a dedicated subagent
context) and automatic routing by `description`.

**Implication for future workdays:** to run `workday`/`publish-site` exactly
as designed — with real `Agent` delegation to `ops-coordinator` and each
department's `subagent_type` — a *fresh* Claude Code session must be started
after the persona/skill files exist, so the harness indexes them at
startup. A workday that must proceed inside an already-open session (as this
one did) should fall back to manual persona embodiment via a generic agent
type (e.g. `general-purpose`) rather than assuming the named
`subagent_type`s are callable. Flagging this to the Executive Office as a
process note, not fixing the charters unilaterally — Operations' job is to
notice and flag, not to redesign another department's docs.
